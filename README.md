# IT爱学堂-AI 业务流架构师训练营
获课：aixuetang.xyz/22890/

技术栈选型与架构模式——从工具对比到链路设计
认知建立之后，训练营进入技术核心。AI 业务流架构师需要掌握的不是某个具体框架的使用，而是根据业务约束选择正确工具组合的决策能力。

四类核心工具的定位差异
当前主流的 AI 业务流工具可以按定位分为四类。n8n 是可视化自动化与 Agent 编排平台，拥有 500 多个预置集成节点，强调把 Agent 放在更大的业务流程中，工作流可以暴露为 API 对外变现，适合“连接器”角色。Dify 是低代码 LLM 应用工厂，聚焦 RAG、工具调用和对话等应用级封装，适合快速把模型能力打包成可交付的产品。Coze 是上手最快的 bot 搭建平台，平台内闭环做得好，但深度定制和跨系统编排的边界明显。LangGraph 是代码优先的状态图框架，原生支持多智能体协作和“人类在环”中断，可编程控制力最强，适合需要强控制的复杂系统。

训练营的核心训练不是让学员背工具功能表，而是建立选型决策树：跨 SaaS 系统集成优先用 n8n，纯 LLM 应用快速上线用 Dify，需要精细控制 Agent 状态和中断恢复用 LangGraph，快速验证 C 端场景用 Coze。很多项目失败的原因不是工具不好，而是工具与场景的错配。

Multi-Agent 协作的四种架构模式
单 Agent 在复杂业务场景中的任务成功率普遍低于 60%，这不是技术问题而是结构问题：一个 Agent 在多个系统之间频繁切换上下文，每次切换都意味着信息丢失和推理偏差，且某个环节出错整个任务链就中断。Multi-Agent 协作架构通过分工拆解将整体成功率提升至 85% 以上。

训练营重点讲解四种协作模式。指挥官-工人模式是最通用的范式，中央编排者负责全局任务拆解、子任务分配和结果汇总，多个专用 Worker 仅执行专属子任务，适合绝大多数企业级场景。层级式模式适合大型复杂项目，按“manager → sub-manager → worker”的树形结构逐级拆解任务。Scatter-Gather 加 Saga 模式处理需要并行探索后合并结果的场景，Saga 提供分布式事务的补偿机制。事件驱动序列模式适用于长时运行、需要外部事件触发的流程。

架构选型的核心原则是：先确定任务的可分解程度，再确定子任务之间是否需要通信，最后确定失败后的恢复策略。这三个问题回答清楚，架构模式自然就确定了。

参考架构的五层关注点
学术界提出的企业级 Multi-Agent 参考架构将系统分为五个关注点：信号接入、编排、专用智能体、行动与集成、治理与人类监督。这个分层框架的价值在于它把“治理”放在与“编排”同等重要的位置，而不是事后再补。训练营中会引导学员用这个框架审视自己的设计方案：信号从哪里进来？编排层用什么协议协调？每个 Agent 的权限边界在哪里？行动层如何保证幂等？治理层如何审计和回滚？
